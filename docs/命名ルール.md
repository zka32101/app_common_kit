# 命名ルール（Petit Works Apps / うかラボ 共通）

迷ったらこの文書に従う。**新規のみ適用**。既存のリポジトリは、まとめて改名する日まで現状維持（§6）。

## 1. リポジトリ名

- 小文字の英数字とアンダースコア（`snake_case`）。ハイフン・大文字・日本語は使わない。
  - 理由: Dart のパッケージ名は `snake_case` が必須。リポジトリ名とパッケージ名を一致させる。
- 数字で始めない。`project-0xx` のような中身の分からない名前を付けない。

| 種類 | 形式 | 例 |
|---|---|---|
| 全アプリ共通の基盤 | `<用途>_kit` | `app_common_kit`, `cross_promo_kit` |
| シリーズ専用の基盤 | `<シリーズ>_core` | `shared_core`（小学コレ） |
| うかラボ共通エンジン | `ukalab_core`（固定。旧名 yourwish_kentei） | |
| うかラボのアプリ | `ukalab_<資格の英語名>` | `ukalab_g_kentei`, `ukalab_boki3` |
| 小学コレのアプリ | `shogaku_kore_<教科>` | `shogaku_kore_programming` |
| その他のアプリ | `<アプリ名>` | `kanken` |

- シリーズ接頭辞は `ukalab_` と `shogaku_kore_`。`shougaku` など別の綴りは使わない。
- 資格名は英小文字の短い名前。級や種別は末尾に付ける（`boki3`, `otsu4`）。

## 2. Dart パッケージ名

- リポジトリ名と同じにする。`pubspec.yaml` の `name:` で食い違わせない。

## 3. バージョンとタグ

- タグは `vMAJOR.MINOR.PATCH`（例: `v0.14.0`）。`pubspec.yaml` の `version` と同じ値にする。
- アプリ側は共通基盤を `ref: vX.Y.Z` で固定する。`main` は参照しない。

## 4. ブランチ・コミット

- 作業ブランチ: `feat/<内容>` `fix/<内容>` `docs/<内容>`（英小文字・ハイフン区切り）。
- コミットメッセージの先頭: `feat:` `fix:` `docs:` `refactor:` `test:` `chore:`。本文は日本語でよい。

## 5. コード・ファイル・データ

- Dart のファイル名は `snake_case.dart`、クラス名は `UpperCamelCase`、変数・関数は `lowerCamelCase`（Dart 公式スタイル）。
- うかラボ向けの公開クラスには `Ukalab` 接頭辞を付ける（例: `UkalabOshiCard`）。全アプリ共通のクラスには付けない。
- 問題データのファイル名: `<資格>_questions.jsonl`。JSON のキーは `lowerCamelCase`（例: `correctAnswer`, `extraReadings`）。
- 級・レベルの値は大文字 `LEVEL_<n>`（既存データに合わせる）。
- `docs/` の文書名は日本語可。

## 6. 既存名の扱い（現状維持）

| 現状 | 新規ルールでの扱い |
|---|---|
| `ukalab-g-kentei`, `ukalab-boki3` など（ハイフン） | 改名候補（`ukalab_g_kentei` など） |
| `sansu-kore`, `kokugo-kore`（ハイフン） | 改名候補 |
| `shougaku-kore-shinshin`（綴り違い） | 改名候補 |
| `project-0xx` | 中身を確認して改名または整理 |

改名すると、各アプリの `pubspec.yaml` の git 依存 URL、CI、ストア設定の参照も変わる。まとめて直す日に、影響範囲を洗い出してから行う。
