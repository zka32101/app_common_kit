# うかラボ 共通運用メモ（別セッション向け）

最終更新: 2026-10-13。ここは公開リポジトリなので、**鍵・トークン・パスワード・個人のメールは書かない**。
不具合の観点は `うかラボ_テスト観点集.md`、共通基盤の使い方は `各資格アプリ向け_共通基盤ガイド.md`。

## 1. 共通部品（app_common_kit・ukalab_core）
- 各アプリは `pubspec.yaml` で、共通基盤を **タグ固定**（`ref: vX.Y.Z`）で参照する。`main` やコミット SHA は参照しない（タグは不変）。キットを直したら、**アプリ側のタグを上げる**（上げ忘れると、直した版が実機に入らない）。上げる作業は、各アプリの `kit-update.yml` が自動で PR にする（`templates/kit-update.yml` をコピーして使う）。
- **キットとコアのタグは揃える**: `ukalab_core` は `app_common_kit` のタグを固定で参照する。アプリがキットの新しい版を使うときは、コアもその版に揃えた版（コアの `pubspec.yaml` の `ref:`）に上げる。食い違うと pub が解決できない。
- どちらに置くか: 全アプリで要る → `app_common_kit`、資格（うかラボ）アプリだけ → `ukalab_core`。うかラボ専用の部品（推し・コイン・衣装・テーマ `UkalabTheme`・用語カード `showTermCard`・ストーリー型 `StoryModeWidget`・学習ラボ）は **`ukalab_core`**（`package:ukalab_core/ui.dart`）にある。キットに置かない。
- 起動画面: `StartupSplash`（中央に読み込み、下部に組織ロゴ）。ロゴは既定で `assets/branding/yourwish_logo.png`。差し替えるときは `OrgBrandingFooter` / `StartupSplash` の `logoAsset`・`logoPackage`・`semanticsLabel`・`footer` を使う（v1.4.0）。
- フォント: G検定は BIZ UDPGothic（SIL OFL 1.1）を同梱。他のアプリへも、字形を揃えたい時は同じ方法（`assets/fonts/` に ttf と `OFL.txt`、`pubspec.yaml` の `fonts:`、`ThemeData.textTheme.apply(fontFamily:)`、`LicenseRegistry` で OFL を登録）。

## 2. Git・PR
- 作業は**専用の作業コピー**（`C:\Users\zka32\wt\<名前>`）で行う。`H:\`（Google Drive）上では Gradle が失敗する（Kotlin のキャッシュ破損）。
- ブランチを切ってから作業し、PR でマージする。マージ前に CI（`gh pr checks`）を待つ。
- push は `gh auth token` を `http.extraHeader` に渡す方式（`credential.helper=` を空にすると認証が失敗する）。
- **ビルド前に必ず `git fetch` して `origin/main` を取り込む**（古い main をビルドして、直したはずの不具合が実機に残った事故あり）。
- コミットの作者は `petitworksappsdev`。Firebase の共有プロジェクトでは `--force` 禁止、`--only` を付ける。

## 3. ビルド（CPU を食うので慎重に）
- ビルドは1本ずつ。複数同時にしない。必要な時だけ行う。
- ローカルの Flutter が新しく、リポジトリの Gradle/AGP/Kotlin が古いアプリは、**ビルド専用の一時変更**（Gradle 8.14 / AGP 8.11.1 / Kotlin 2.2.20）を作業コピーにだけ入れる。**コミットしない**。
- `flutter build` が不安定な時は `android\gradlew.bat assembleDebug` が通ることがある。
- `google-services.json` はリポジトリに無い（CI が生成）。作業コピーへコピーするだけで、コミットしない。

## 4. 実機テスト
- 実機は複数台。**`adb -s <シリアル>` を必ず付ける**（先頭の端末を自動で選ばない）。ユーザーの別端末には触らない。
- USB は、大きな APK（約180MB）の転送中に切れやすい。**無線 adb**（`adb connect <IP:ポート>`）なら入る。ワイヤレスデバッグのポートは、毎回変わる。
- PowerShell の `>` で screencap を保存すると壊れる。`adb shell screencap -p /sdcard/x.png` → `adb pull`。Git Bash はパスを書き換えるので、`/sdcard/...` を使う adb は PowerShell で実行する。
- 署名が違う旧版が入っていると上書きできない（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。テスト端末ではアンインストールして入れ直す（学習データは消える）。
- 課金の確認は、ライセンステスターの**テスト購入**（請求なし）で、購入画面の価格・反映までを見る。
- **Play 経由で入れた版でないと**、定期購入の商品は取得できない（PC 経由の署名違いの版では「商品情報を取得できません」）。Play の内部/クローズドテストに上げ、端末に入れてから、購入シートが開くところまで確認する（購入は確定しない）。
- 初回起動は、**アンインストール後の新規インストール**で、オンラインと機内モードの両方で確認する（既存データがあると再現しない）。審査で「アプリが開かない」とされた原因は、起動時の画面遷移（ルート定義）の欠落だった。
- 広告を出すアプリは、操作中に広告を誤タップして外部のストアが開くことがある。戻って、何もインストールされていないか確認する。

## 6. 全アプリへの展開
- 以前ここにあった「起動画面の組織ロゴ」の進行状況（2026-10-06 時点）は古いので消した。現状は各アプリのリポジトリ（`lib/` の起動画面と `pubspec.yaml`）で確認する。
- 展開の仕組み: キット／コアに新しいタグが出ると、各アプリの `kit-update.yml` が更新 PR を作る（マージは人。**リポジトリの設定「Allow GitHub Actions to create and approve pull requests」をオンにする必要がある**）。リリース前には、キットの `compat` CI が 5 アプリに差し込んで analyze／test を走らせる。
- 不具合報告 → Issue → 修正 PR: 各アプリに `templates/autofix-issue.yml` を入れ、リポジトリの Secrets に `ANTHROPIC_API_KEY` を登録する。人が内容を確認して `autofix` ラベルを付けた Issue だけ、修正 PR を作る。
