# うかラボ 共通基盤ガイド（各資格アプリの作成セッション向け）

作成: 2026-10-02（2026-10-13 更新: キット v3 系・コア v0.6x 系の分担に合わせて全面更新）/ 対象: 各資格アプリ（G検定・乙4・簿記3級・ITパス ほか）を作るセッション
このガイドは、共通基盤（`app_common_kit`・`ukalab_core`）を使ってアプリを作る人が、**先に知っておくべきこと**をまとめたもの。迷ったら各リポジトリの README と CHANGELOG が正。

## 1. 構成と依存の向き

```
資格アプリ（薄いリポジトリ） → ukalab_core（試験エンジン＋うかラボ専用UI） → app_common_kit（全アプリ共通の部品）
```

- 依存は **タグ固定**（`ref: vX.Y.Z`）。`main` は参照しない。タグは不変で、付け替えない
- **どちらに置くか**: 全アプリで要る → `app_common_kit`、資格（うかラボ）アプリだけ → `ukalab_core`。迷ったら、他のシリーズ（小学コレなど）でも要るかで決める
- **キットとコアのタグは揃える**: `ukalab_core` は `app_common_kit` のタグを固定で参照している（コアの `pubspec.yaml` の `ref:`）。アプリはキットとコアを**同じキットのタグ**で使う。食い違うと pub が解決できない。キットを上げるときは、コアもその版に揃えた版を出す
- 資格アプリが持つのは: 試験定義（ExamConfig の JSON）、問題データ、資格ID（テーマ・アイコン用）、ストア設定。共通の仕組みは自分で作り直さない
- 共通の部品に足りないものを見つけたら、アプリ側に独自実装せず、共通側の issue／PR にする（他の資格でも要る可能性が高い）
- 版は動くので、このガイドには書かない。最新のタグは各リポジトリの `CHANGELOG.md` か `git ls-remote --tags <url>` で確認する。**キットの番号とコアの番号は別**（無関係）
- 破壊的変更は major を上げて CHANGELOG に移行手順を書く。**キットは v1.0.0（うかラボ専用UIをコアへ移した）、v2.0.0（学習ラボ系・用語カード等をコアへ移した）、v3.0.0（コア専用の文言をコアの `UkalabStrings` へ移した）で破壊的変更があった**。古い版（v0.x）の使い方が出てきたら、CHANGELOG の移行手順を見る

| リポジトリ | 中身 |
|---|---|
| `zka32101/app_common_kit` | 全アプリ共通の部品（下の「2. キットでできること」） |
| `zka32101/ukalab_core` | 試験定義、問題モデル、問題データ検証、模擬試験の採点、間隔反復、演習、無料版の線引き。うかラボ専用のUI（`package:ukalab_core/ui.dart`）: 推し・コイン・衣装・テーマ `UkalabTheme`・合格報告・用語カード・ストーリー型・学習ラボ・アイコン生成（`tools/icon_gen`）。Firebase 共有プロジェクトのルール（`firebase/`） |

**資格の追加は共通側の作業**: `UkalabCert` にない資格（衣装・テーマ・アイコンに必要）は、`ukalab_core` にPRを出して新しいタグを切る。アプリ側で独自に作らない。

**採用状況**: 2026-10-03 の記録（bike・kanken を手本にした）は古いので消した。各アプリが使っているタグは、各アプリの `pubspec.yaml` で確認する。手本にしてよいアプリは「9. 手本になるリポジトリ」を見る。

## 2. 共通基盤でできること

### app_common_kit（全アプリ共通）
- **権利管理**: `EntitlementService`（RevenueCat）。権利は `noads`（広告なし）と `premium`。premium は広告も出ない。テスト・開発用に `FakeEntitlementService`。設定画面の購入欄 `PurchaseSection`
- **広告ゲート**: `AdGate`。同意取得（UMP）、インタースティシャルは「学習セッション終了」「模擬試験の結果」の2場面のみ（最短3分、1日5回まで）、バナーはホーム・結果・弱点ドリルのみ。有料時は広告を初期化しない。リリースビルドでテスト広告IDを使っていると検知する
- **フィードバック**: 送信フォーム、オフラインキュー、GitHub Issue 自動化（Cloud Functions のテンプレート）。Issue から修正 PR までは `templates/autofix-issue.yml`
- **設定画面**: `SettingsScreen`（受験日・購入・表示モード・言語・ながら学習・フィードバック・データ削除・法務リンク・このアプリについて。項目は任意）。言語は内蔵の ja・en・zh・zh-Hant・ko（zh・zh-Hant・ko は機械翻訳の下書き）
- **アプリ内レビュー依頼**（`ReviewPromptService`）、**強制アップデート・お知らせ**（`UpdatePolicy`・`UpdateBackend`）、**分析の窓口**（`Analytics`。個人情報の混入を防ぐ）、**クラッシュ収集の窓口**（`CrashReporter`）
- **データ削除の窓口**（`DataDeletion`。ストア審査・プライバシー対応）、**法務リンク**（`LegalLinks`。文面は含めない。`法務文書_確認用チェックリスト.md` を見る）
- **音声読み上げ・ながら学習**（`FlutterTtsSpeechBackend`・`HandsFreeChoiceBody` など。`hands_free_tts.dart` の入口）、**解答時の音と触覚**（`AnswerFeedback`。音の再生はアプリが `SoundBackend` で実装）
- **共通UI部品**: `QuestionCard`・`ChoiceTile`（正誤は✓／✕＋文言）・`ExplanationPanel`（出典つき）・`ProgressRing`・`StreakBadge`・`ResultSummary`・`EmptyState`・`ErrorState`・`OrgBrandingFooter`／`StartupSplash`（ロゴは差し替え可）
- **アクセシビリティの自動検査**（文字拡大200%・タップ領域・読み上げラベル。`test/accessibility_test.dart`）
- 現状、学習寄りの部品（受験日 `ExamDateTile`・連続学習 `StreakBadge`・`recordStudyToday`／`loadCurrentStreak`・ながら学習など）もキットに入っている。これらをコアへ移すかどうかは未決（キットは学習に限らない共通基盤にしたい方針）

### ukalab_core（資格アプリ専用）
- `ExamConfig`（試験定義）、`Question`、`validateQuestions`（配信前の品質ゲート）、`scoreMockExam`（合否・足切り・あと何点）、`Srs`、`PracticeSession`、`UsageQuota`・`FreeTierLimits`
- 問題データ検証 CLI: `dart run ukalab_core:validate_content exam.json questions.jsonl`
- **うかラボ専用UI**（`import 'package:ukalab_core/ui.dart';`）:
  - テーマ: `UkalabTheme.light/dark(field:, cert:)`。分野・資格ごとの色。**色を直書きしない**。コントラストは AA を満たす検査済み
  - 推し: `MascotWidget`、`MasteryModel`（習得度→Lv1〜5）、`UkalabOshiCard`、セリフと禁止表現チェック
  - 学習コイン `CoinService`（学習の成長でだけ増える。財布は**アプリごと**）、衣装 `OutfitService`・着替え・ショップ `WardrobeScreen`、合格報告 `showPassReportDialog`、準備完了 `ReadinessRule`、コイン内訳 `CoinBreakdownCard`、共有カード `PassShareCard`
  - 専門用語の解説 `TermCard`・`TappableTermText`、ストーリー型 `StoryModeWidget`、学習ラボ（境界線スライダーなど）
  - アイコン生成 `tools/icon_gen`（試験名・シンボルSVG・資格IDから量産。検査つき）
- 画面専用の文言は `UkalabStrings`（`UkalabStrings.of(context)`）。共通の画面の文言は `KitStrings`（キット）

## 3. 新しい資格アプリを作る手順

1. 資格IDを決める（`UkalabCert` に既にあるか確認。ない資格は共通側に追加する）
2. `pubspec.yaml` に依存を追加（**タグ固定**）
   ```yaml
   app_common_kit:
     git: { url: https://github.com/zka32101/app_common_kit.git, ref: vX.Y.Z }
   ukalab_core:
     git: { url: https://github.com/zka32101/ukalab_core.git, ref: vA.B.C }
   ```
   `vX.Y.Z` と `vA.B.C` は、各リポジトリの最新のタグ。ただし**コアが固定しているキットのタグ**（コアの `pubspec.yaml` の `ref:`）と、アプリのキットのタグを同じにする
   `google_mobile_ads` は **5.3.1 以上**（4.x では同意取得のAPIがなくビルドできない）
3. 試験定義 JSON と問題データを置き、`validate_content` を CI に入れる
4. テーマ: `UkalabTheme.light/dark(field:, cert:)`。色の直書きをしない
5. 権利管理・広告・推し・コイン・衣装: 手本は `bike`（バイク免許コレ）と `kanken`（漢字マスター検定）の `lib/main.dart` と `lib/widgets/oshi_card.dart`（推し・コイン・衣装は `ukalab_core/ui.dart`）。起動時に `CoinService(store: SharedPreferencesCoinStore('<appId>'), shop: OutfitCatalog.shopItems([cert]))` と `OutfitService(store: SharedPreferencesOutfitStore('<appId>'))` を作って override する
6. アイコン: `tools/icon_gen` に資格ID・試験名・シンボルを足して生成。検査を通す
7. ストアの免責表示（試験団体との無関係、非公式であること）。手本は kanken の設定画面「このアプリについて」

## 4. 守るルール（全資格共通）

- **無料版の線引き**: 問題・解説は全て無料。制限するのは模擬試験の回数（月1）、苦手分析（上位3分野）、復習の量（1日10問）などの**機能の量**（暫定値は `FreeTierLimits`）
- **価格**: 広告なし ¥480。premium は 30日 ¥600／90日 ¥1,000／買い切り ¥1,500。広告も課金も、学習の可否には使わない
- **コイン**: 学習の成長でのみ増える。**課金・広告視聴で付与しない**。使い道は見た目だけ
- **推し・セリフ**: 責める・いなくなる・恋愛依存を煽る表現は禁止（検査あり）。ランキング・他人との比較なし
- **試験団体のロゴ・制服・公式の意匠は使わない**。「公式」「認定」の文字も使わない。アイコンに AI 画像は使わない
- **色だけに頼らない**（✓／✕・文言を併記）。文字拡大200%で崩れない。タップ領域44pt以上
- **秘密情報（鍵・トークン）をリポジトリに置かない**

## 5. 問題データの品質（バイク免許コレの教訓）

バイク免許コレの問題データを確認して、次のことが分かった。**他の資格でも同じ失敗が起きうる**。

- **AIによる問題の査読は信用しすぎない**。標識の色・形、法改正の指摘に誤りがあった（例: 二人乗りの条件を「廃止済み」と判断したが、現行法に残っていた）。**必ず一次資料の本文で確認する**
- 一次資料の取得方法（無料・機械的に取れる）:
  - 法令: e-Gov 法令API（`laws.e-gov.go.jp/api/2/law_data/{法令ID}`）。施行令・施行規則・標識令も取れる。添付画像は `api/2/attachment/{法令履歴ID}`
  - 告示（教則など）: 警察庁のサイトに全文PDFがある。省庁の告示は著作権の対象外（著作権法13条）
- 問題データには**出典欄**を付ける（`sourceRef`＝短い参照、`lawVersion`＝確認日）。出典のない問題は「未確認」。解説に「根拠」を書く場合も、欄に分ける
- 見つかった典型的な誤り: 選択肢の並び違いだけの重複問題、正解が一番長い（約66%）、駐停車禁止と駐車禁止の取り違え、「大回り」を正解にした右左折、標識の色や分類の取り違え、存在しない事実を前提にした問題
- 回帰テストを入れる: 確認した事実（数字・条文）はテストにする（バイクの `question_data_test.dart` が手本）
- **法令は改正される。出典の確認日と施行版を必ず記録する**。バイク免許コレでは、2026-09-01 施行の施行令第11条で、一般道路の法定最高速度が「中央線または車両通行帯のある道路は60km/h、**それ以外の一般道路は30km/h**」に変わっていた。「標識がなければ一般道は60km/h」と書いた問題が、現行法と合わなくなっていた。確認は必ず**現行の条文**で行う
- **出典づけは、引用の逐語一致を機械で確認する**。AIに根拠の条文や教則の文を探させると、実在しない引用や、主張の一部しか裏づけない引用が混ざる。(1) 引用は資料の本文に実在する文字列のコピーに限る、(2) 一致しないものは破棄する、(3) 「記載なし」「一部のみ」と注記された弱い根拠には出典を付けない、(4) 本文と矛盾した問題（WRONG）は個別に直すか削除する。バイクでは1,269問を照合し、出典を付けられたのは806問、本文と矛盾したのは9問だった。手順は `bike/docs/question_review/README.md`
- **出典がない＝誤り、ではない**。本文に書かれていない運転技術や一般論は、法令・教則では確認できない。出典なし（未確認）のまま、配信の扱いは運営者が決める（決定ログ10）
- 標識など**図が要るもの**は、画像を持ち込まずコードで描く（バイクの `traffic_sign_painter.dart`）。公式の図（標識令）で形・色を照合する

## 6. 環境の注意（Windows・日本語パス）

- `H:\マイドライブ\...` は日本語パスなので Android ビルドが失敗する。**英語パスのクローンで作業・ビルド**する（例: `C:\Users\zka32\wt\<アプリ名>`）
- `git add -A` は使わない。Flutter が `android/` を書き換えてコミットに混ざる。`lib`・`test`・`docs` などを指定して add する
- `git stash`（引数なし）は共有リポジトリで使わない
- ファイルに `\n` を含む Dart の文字列を Python などで書くと、本物の改行に化ける。ファイル書き込みは Write ツールを使う
- 実機は**共用**。他のアプリの試験中かもしれないので、合図なしに操作しない
- マージ・タグ付け・ストアへの公開は、ユーザーの指示があってから

## 7. ユーザー側の作業が要るもの（コードでは終わらない）

- **Firebase 共有プロジェクト**（`ukalab-prod`／`ukalab-dev`）: **作成済み**（2026-10-03）。Firestore（東京）とルールは配備済み（`ukalab_core` の `firebase/` を参照）。残り: Authentication の匿名・Google・Apple の有効化（画面操作。API 経由は課金が必要）、Analytics、Crashlytics、各アプリの接続（資格ごとにアプリを登録して設定ファイルを置く）。新しい資格を足したら `ukalab_core` の `firebase/firestore.rules` の `examIds()` に id を追加して配備する
- **課金の商品登録**: Play Console と RevenueCat に、`noads`・`premium`（30日・90日・買い切り）を登録し、権利（entitlement）と紐付ける
- **AdMob**: 広告ユニットIDの発行、UMP（同意）メッセージの設定
- **ストア掲載**: スクリーンショット、説明文、プライバシーポリシー、広告ID・AI生成コンテンツの申告
- 注意: Play Console の変更は「保存」と「審査に送信」が別。送信はユーザーが行う

## 8. 未決・未実装（作る前に確認）

- 習得度の式と段階の境目（暫定: 網羅率×正答率、0.2／0.4／0.6／0.8）
- コインの獲得量・価格、通常衣装の価格（暫定300）、衣装の無料／premium線引き
- アイコンのシンボルの最終デザイン（現状は仮）
- 他キャラ（男性・女性・動物）の画像パックと口調別セリフ
- 学習体験の「型」（境界線スライダー・予測→実行・推しの添削・最短ルートプランナー）は `ukalab_core` 側で v0.3 以降。G検定の実装に合わせて作る
- 準備完了の判定は暫定（最短ルートプランナーが完成したら、そちらの「目標達成」に置き換える）
- コイン残高の共通アカウント同期: `FirebaseCoinRemote`・`CoinNotifier.syncWith` まで実装済み（README「共通アカウントで同期する」）。各アプリは uid を渡して起動時・購入後に呼ぶだけ。残りは Firebase の認証（匿名・Google・Apple）を、ユーザーが画面で有効にすること
- 練習・対戦・単発の試験の結果画面へのコイン内訳（kanken）
- UI の多言語化: `KitStrings`/`KitStringsScope` の土台と一部ウィジェットは対応済み。残りのウィジェットを順次移行
