# Google Play ASO ルール

最終更新: 2026-10-08
対象: Google Playで配信する全アプリ（Petit Works Apps）。リリース前・掲載情報の変更前に必ず確認する。

凡例: **[公式]** = Google公式の要件・ポリシー / **[目安]** = 業界調査・事例ベース（Google非公表）

---

## 1. 文字数・フィールドの基本 [公式/目安]

| 項目 | 上限 | 役割 |
|---|---|---|
| タイトル | 30文字 | 最重要のキーワード欄。順位への影響が最大 |
| 短い説明 | 80文字 | 検索結果に表示。CVR重視、キーワードも効く |
| 長い説明 | 4,000文字 | キーワードを自然に配置。冒頭数行がCVRに直結 |

- iOSと違い、非表示のキーワード欄はない。
- 長い説明では重要語を3〜5回程度、自然に使う（密度の目安は約3%）。

## 2. やること（MUST）

1. **タイトルは「ブランド名＋主要キーワード1〜2語」**。重要語は先頭付近に置く。
2. **短い説明**は、ダウンロードする理由を1文で伝える。キーワードは1〜2語まで。
3. **長い説明**は、機能・メリット・使い方を箇条書きと短い段落で書く。
4. **ローカライズ**は直訳せず、市場の言葉に合わせる（日本向けは日本語で最適化）。
5. **キーワード選定の前に競合を調べる**。競合のタイトル・短い説明・説明文で狙いを把握する。
6. **公開前にAndroid vitalsを整える**: クラッシュ率 1.09%未満、ANR率 0.47%未満（Google公式のbad behaviorしきい値）。
7. **公開直後に告知を集中**させ、インストール速度を作る（新規は一般キーワードで順位がつくまで2〜6週間かかる目安）。
8. **説明と実機能を一致**させる（ズレはアンインストール増→順位低下）。
9. **評価・レビューに対応**し、定期的にアップデートする。
10. **年1回はタイトル・説明を棚卸し**する（頻繁な変更はしない。第4章参照）。

## 3. やってはいけないこと（MUST NOT）

### メタデータ [公式]
- タイトル・アイコン・開発者名に「トップ」「#1」「ベスト」「無料」「広告なし」などを入れない。
- 絵文字・顔文字・繰り返し記号（!!!）を使わない。ブランド名以外の全大文字も不可。
- 「今すぐダウンロード」等の行動喚起を、タイトル・アイコン・スクショ・動画に入れない。
- 出典のない・匿名の「ユーザーの声」を説明文に載せない。
- タイトルは30文字以内（50文字のまま放置した場合、30文字目以降のキーワード順位が下がった例あり）。

### キーワード [目安]
- 同じ語の詰め込みをしない（大量に入れても順位が付かなかった例あり）。
- タイトルを頻繁に変えない、CVRの高いキーワードを安易に消さない。
- 実際の機能にない語を入れない。

### 順位・数字の操作
- 評価・レビュー・インストール数を不正に操作しない。報酬付きの「検索インストール」施策もしない。
- 詳細は最新のGoogle Playポリシーセンターで確認すること。

### 技術・運用 [公式/事例]
- クラッシュ・ANRのしきい値超過を放置しない（表示抑制の対象）。
- 動的コード更新（ホットアップデート）で審査を回避しない。
- プライバシーポリシーに違反しない（DL急上昇中でも削除された実例あり）。

## 4. 順位・露出に効く要因

| 要因 | 内容 | 区分 |
|---|---|---|
| 関連性 | タイトル・説明のキーワード、カテゴリ、画像・動画 | 公式 |
| 品質 | 技術性能、UX、評価・レビュー | 公式 |
| インストール速度 | 総数より直近の勢い。急増後に落ちると5〜10日で順位も下がる傾向 | 目安 |
| リテンション・アンインストール | 7日以内のアンインストール率が高いと不利 | 目安 |
| Android vitals | クラッシュ率・ANR率のしきい値超過で抑制 | 公式 |
| CVR | キーワード別のCVRも順位に影響 | 目安 |
| リテンション目安 | Day1 35%超、Day7 15%超が上位と関連する、という業界目安 | 目安（非公式） |

## 5. ストア掲載情報のA/Bテスト（掲載情報の試験運用）

- **順番**: アイコン → スクショ → 短い説明（Googleの推奨順。フィーチャーグラフィックも優先度高）。
- **1回に1要素だけ**変える（アイコンとスクショの同時変更は不可）。
- **7日以上**回す（早期に勝って見えても打ち切らない）。
- **地域を絞る**（日本のみ等）。全世界で一斉にやらない。
- **既存の認知ブランドのアイコンを大きく変えない**（Spiegel事例: インストール減）。
- 影響度の目安（業者集計）: アイコン10〜30%、スクショ5〜20%、短い説明2〜8%、長い説明1〜5%。

## 5-2. スクリーンショット・フィーチャーグラフィック・動画

### スクリーンショット [公式]
- 端末タイプごとに**最大8枚**。JPEGまたは24bit PNG（アルファなし）。
- 各辺320〜3,840px。縦横比は16:9（または9:16）の範囲に収める。推奨サイズ例: 1080×1920。
- **アプリのUIだけを見せる**。端末の向きを正しく回転させておく。
- ゲームは横向きスクショが大きく表示される面があり、アイコンのみより高いCVRになるとGoogleは説明している。
- 「今すぐダウンロード」等の行動喚起は入れない（第3章）。
- 短い説明・スクショ・フィーチャーグラフィック・動画で**メッセージを重複させない**。

### スクリーンショットの目安 [目安]
- 4枚以上（解像度の下限あり）がおすすめ表示の目安とする情報がある。公開前にヘルプで最新要件を確認する。
- 1枚目は「このアプリで何ができるか」を1つの約束として見せる。フィーチャーグラフィック・動画の最初のフレームと同じ訴求に揃える。
- スクショへの説明文追加は、効果が出ないこともある（Spiegel事例）。必ずテストで確認する。

### フィーチャーグラフィック [公式]
- **必須**。1024×500px、JPEGまたは24bit PNG（アルファなし）。
- 動画がある場合、再生ボタンのカバー画像として表示される。
- 端が切り取られる表示面があるため、重要な要素は中央の安全領域に置く。
- 動画なしの場合の表示は、掲載面や時期で変わりやすい。最新のヘルプで確認する。

### プロモーション動画 [公式]
- 動画は**任意だが推奨**（特にゲーム）。**1掲載につき1本**。
- **YouTubeのURL**を入力（フルURL `youtube.com/watch?v=…`。再生リスト・チャンネルURLは不可）。
- 公開または限定公開、埋め込み可。**年齢制限なし**。
- **広告・収益化をオフ**にする（ONだとプレビューが壊れる）。
- スクショより前に表示され、端末や通信状況により**ミュートで最大30秒まで自動再生**されることがある。自動再生されない場合はフィーチャーグラフィックに再生ボタンが重なる。
- 動画は横向き（16:9）。縦向きアプリは左右に黒帯が入る。動画を入れると縦向きスクショの表示が小さくなる情報もある。

### 動画の制作・運用の目安 [目安]
- 長さは15〜30秒、冒頭の数秒で価値を伝える（ミュート前提で字幕・テロップを使う）。
- 実際のアプリ体験を中心にし、誇張や誤解を招く映像は避ける（実機映像が大半という目安あり）。
- 動画の効果は一律ではない。業界の検証では15〜25%のCVR向上例があるが、動画だけでDLが増える保証はない。
- 動画のURL・公開設定・広告設定・字幕・フィーチャーグラフィック・確認日を、ロケール別に管理表へ記録する。
- 子ども向けアプリでは、動画の内容も対象年齢に適したものにする（年齢制限付き動画は不可）。

### テストの扱い
- アイコン→スクショ→短い説明の順で、動画・フィーチャーグラフィックは別の回に分けて検証する（第5章の原則を適用）。
- スクショは「セット全体」をテスト単位にし、順序もテスト対象にできる。

## 6. 子ども向けアプリの追加ルール（小学コレ！など）

- 対象年齢を正確に申告する（申告内容は審査対象。不備は公開拒否・削除の原因）。
- 子ども主体のアプリは**Designed for Families**の対象になり得る。広告は**認定SDK・ネットワークのみ**使用。
- 一般向けと兼ねる場合は年齢確認（age gate）が必要になることがある。
- アイコン・スクショのキャラ表現は、審査で見直しを求められる場合がある。
- 要件は更新されるため、公開前にPlayコンソールヘルプで必ず確認する。

## 7. 掲載文の雛形（案。要調整）

**小学コレ！**
- タイトル: `小学コレ！算数・国語ドリル｜キャラ集め`
- 短い説明: `キャラを集めながら小学生の算数・国語を学べるドリルアプリ。毎日の家庭学習が楽しく続く！`

**うかるラボ**（資格名は〇〇に置換）
- タイトル: `うかるラボ 〇〇 過去問`
- 短い説明: `〇〇の過去問・一問一答を解説つきで学習。スキマ時間にマスコットと一緒に合格を目指そう！`

雛形の注意:
- 「合格保証」「絶対合格」などの誇大表現は使わない。
- 過去問を使う場合は、出題機関の著作権表記を説明文に入れる（競合は入れている例が多い）。
- 「累計DL」などの実績は、自アプリの事実のみ。
- 年号（2026）入りは最新性を示せるが、毎年のタイトル変更は順位リスクになるため、運用方針を決めてから採用する。

- [ ] 長い説明: 冒頭数行が魅力的、詰め込みなし、匿名の声なし

- [ ] プライバシーポリシー・動的コード・SDKがポリシー適合
- [ ] 子ども向けの場合: 対象年齢の申告、Families要件、認定広告SDK
- [ ] スクショ: 端末タイプごと最大8枚、UIのみ、行動喚起なし、1枚目で訴求が伝わる
